# RulesHorror 챕터/씬 상세 분해 기획서

## 0. 문서 목적

이 문서는 기존 `스토리기획.md`, `개발기획.md`, `프로토타입_씬별_필수구성요소.md`를 실제 StoryFlow/UE5 작업 단위로 옮기기 위해 작성한다.

목표는 다음과 같다.

- 챕터 단위 기획을 **씬 단위**로 쪼갠다.
- 각 씬을 StoryFlow Scene / Shot / Branch 작업으로 바로 옮길 수 있게 한다.
- 프로그래머, 레벨 디자이너, UI/연출 작업자가 같은 기준으로 작업할 수 있게 한다.
- 미니게임 본구현 전에도 `시작 → 허브 → 추격 → 병실 엔딩`의 더미 완주가 가능하도록 한다.

---

## 1. 작업 단위 정의

### 1-1. Chapter
큰 서사 구간이다. 플레이어가 기억하는 이야기의 덩어리다.

예시:
- CH01: 신문사 도입
- CH02: 첫 번째 낙인 - PC방 규칙괴담
- CH06: 병실 엔딩

### 1-2. Scene
실제 제작/검증 단위다. 다음 중 하나가 바뀌면 별도 Scene으로 본다.

- 맵 또는 공간이 바뀐다.
- 플레이 목적이 바뀐다.
- 조작 상태가 바뀐다.
- 컷신/연출 중심에서 탐색/플레이 중심으로 바뀐다.
- 저장 체크포인트로 삼을 만한 지점이다.

### 1-3. StoryFlow Shot
씬 내부에서 순차 실행되는 가장 작은 연출/진행 단위다.

예시:
- 페이드 인
- 플레이어 입력 잠금
- 자막 표시
- 카메라 강제 전환
- 특정 오브젝트 상호작용 대기
- 다음 씬으로 전환

### 1-4. 저장 기준
Scene은 플레이 흐름의 **체크포인트 단위**로 사용한다. 다만 실제 저장/복구의 최소 단위는 **Shot**이다.

- Scene 진입 시 `CurrentSceneID`를 갱신한다.
- Shot 시작 또는 복구 가능한 중요 Shot 진입 시 `CurrentShotID`를 갱신한다.
- 이어하기/로드는 `CurrentSceneID`만으로 대략적인 위치를 잡고, `CurrentShotID`로 실제 재개 지점을 확정한다.
- 컷신 중간, 상호작용 대기, 미니게임 시작/클리어, 씬 전환 직전처럼 복구 의미가 있는 지점은 반드시 ShotID 저장 후보로 본다.
- Scene은 저장 체크포인트의 묶음이고, Shot은 저장 복구의 최소 좌표다.

## 2. ID / 네이밍 규칙

### 2-1. StoryFlow SceneID
형식:

```text
CH##_S##_EnglishSlug
```

예시:

```text
CH01_S01_OfficeWake
CH01_S04_CrosswalkAccident
CH06_S03_SpeechChoice
```

### 2-2. StoryFlow ShotID
형식:

```text
S##_Shot##_VerbObject
```

예시:

```text
S01_001_FadeInOffice
S01_020_WaitDeskInspect
S04_030_PlayCarImpact
```

### 2-3. Save / 진행 상태 키 후보
최소 프로토타입 단계에서 필요한 값이다.

| 키 | 용도 |
|---|---|
| `CurrentChapter` | 현재 챕터 |
| `CurrentSceneID` | 마지막 진입한 StoryFlow SceneID. 체크포인트 묶음 단위 |
| `CurrentShotID` | 마지막 저장 가능 StoryFlow ShotID. 실제 이어하기 최소 단위 |
| `Brand_01_Oppression` | 첫 번째 낙인 획득 여부 |
| `Brand_02_Bystanding` | 두 번째 낙인 획득 여부 |
| `Brand_03_Exploitation` | 세 번째 낙인 획득 여부 |
| `Scenario_01_Clear` | PC방 시나리오 클리어 여부 |
| `Scenario_02_Clear` | 무궁화 시나리오 클리어 여부 |
| `Scenario_03_Clear` | 숲 탈출 시나리오 클리어 여부 |
| `EndingUnlocked` | 병실 엔딩 진입 가능 여부 |

# CH01. 신문사 도입

## 챕터 목적
- 주인공의 현재 처지, 좌천, 해고 위기, 딸 부양 압박을 전달한다.
- 수신불명 전화와 괴담 사이트 제보를 통해 사건을 시작한다.
- 횡단보도 사고로 현실 레이어를 끊고 꿈 레이어로 진입한다.

## 챕터 구현 우선도
- **최우선 세로 슬라이스 대상**.
- 미니게임 없이도 게임 시작부를 검증할 수 있어야 한다.

## CH01_S01_OfficeWake

| 항목 | 내용 |
|---|---|
| 씬 목적 | 플레이어를 좌천된 기자의 사무실 자리에서 시작시킨다. |
| 공간 | 신문사 좌천 부서 사무실. |
| 맵 후보 | `/Game/Maps/L_Office` |
| 플레이 상태 | 제한적 자유 이동 / 조사 가능. |
| 시작 트리거 | 본편 시작 또는 테스트용 직접 시작. |
| 종료 조건 | 필수 조사 오브젝트 1개 이상 확인 후 다음 씬 진입. |
| 저장 지점 | `CurrentSceneID = CH01_S01_OfficeWake`, `CurrentShotID = S01_001_FadeInOffice`부터 Shot 단위 갱신 |

### 핵심 감정
- 초라함
- 피로감
- 회사에서 밀려난 느낌
- 그래도 다시 올라가고 싶어 하는 욕망

### 필수 오브젝트
- 주인공 책상
- 낡은 모니터 또는 꺼진 PC
- 경고장/인사 통보 문서
- 가족사진
- 빈 커피컵/신문 더미
- 멀리 보이는 다른 부서의 밝은 공간 또는 닫힌 문

### StoryFlow Shot 구성

| ShotID | 내용 | 구현 메모 |
|---|---|---|
| `S01_001_FadeInOffice` | 어두운 사무실에서 페이드 인 | 입력 잠금 |
| `S01_010_ShowDeskView` | 책상/모니터 방향으로 시선 유도 | 카메라 보간 또는 플레이어 시작 회전 |
| `S01_020_UnlockInvestigation` | 조사 입력 해금 | 상호작용 가능 상태 전환 |
| `S01_030_WaitRequiredInspect` | 필수 오브젝트 확인 대기 | 경고장 또는 가족사진 중 1개 이상 |
| `S01_040_EnableExitTrigger` | 퇴근/전화 흐름 트리거 활성화 | 문/복도/전화 이벤트 준비 |
| `S01_050_GotoOfficeInspect` | 다음 씬으로 이동 | `CH01_S02_OfficeInspect` |

### 구현 작업 체크리스트
- [ ] StoryFlow SceneAsset 생성: `CH01_S01_OfficeWake`
- [ ] TargetLevel을 사무실 맵으로 지정
- [ ] 시작 위치 Actor 배치
- [ ] 조사 가능 오브젝트 1~3개 배치
- [ ] 조사 완료 플래그를 StoryFlow Shot에 전달할 방법 결정
- [ ] 다음 Scene으로 이동하는 링크 설정

### 검증 기준
- 본편 시작 지점 또는 Play From Shot으로 시작 가능하다.
- 플레이어가 최소 1개 오브젝트를 조사할 수 있다.
- 조사 후 다음 씬으로 넘어갈 조건이 열린다.

## CH01_S03_UnknownCall

| 항목 | 내용 |
|---|---|
| 씬 목적 | 수신불명 전화로 괴담 사이트와 실종 사건 제보를 전달한다. |
| 공간 | 사무실 출구/복도 또는 퇴근 직전 공간. |
| 플레이 상태 | 입력 일부 제한, 전화 연출 중심. |
| 시작 트리거 | 퇴근 동선 진입. |
| 종료 조건 | 주인공이 다시 회사로 돌아가려는 결심. |

### 연출 요지
- 전화벨이 갑자기 울린다.
- 발신자 정보가 없다.
- 상대는 최근 실종자들의 컴퓨터에 공통으로 뜬 괴담 사이트를 언급한다.
- 주인공은 특종 욕심 때문에 다시 회사로 돌아가려 한다.

### 대사/자막 기능 요구
- 발신자 표기: `수신불명`
- 통화 자막 UI
- 전화 종료 후 내면 독백 1~2줄

### StoryFlow Shot 구성

| ShotID | 내용 | 구현 메모 |
|---|---|---|
| `S03_001_LockInputForCall` | 입력 잠금/전화벨 재생 | 사운드 필요 |
| `S03_010_ShowUnknownCaller` | 수신불명 UI 표시 | UI 더미 가능 |
| `S03_020_PlayTipOffDialogue` | 실종 사건/괴담 사이트 제보 | 자막 중심 |
| `S03_030_PlayerGreedMonologue` | 특종 욕망 내면 독백 | 반성 없음 강조 |
| `S03_040_UnlockReturnRoute` | 회사 복귀 동선 활성화 | 도로/횡단보도 씬으로 연결 |
| `S03_050_GotoCrosswalk` | 사고 씬으로 이동 | `CH01_S04_CrosswalkAccident` |

### 검증 기준
- 전화 내용만으로 다음 행동 이유가 이해된다.
- 주인공이 “속죄”가 아니라 “특종/출세” 때문에 움직인다는 점이 드러난다.

# CH02. 첫 번째 낙인 - 꿈속 허브 / PC방 규칙괴담

## 챕터 목적
- 플레이어가 현실이 아닌 꿈/잠재의식 레이어에 들어왔음을 느끼게 한다.
- 괴담 사이트 `종막실` 또는 최종 확정 사이트에 첫 접속한다.
- 첫 번째 시나리오인 PC방 규칙괴담으로 진입한다.
- 첫 번째 낙인, 즉 억압의 죄를 획득한다.

---

## CH02_S01_DreamHubAwake

| 항목 | 내용 |
|---|---|
| 씬 목적 | 사고 후 플레이어가 이상한 허브 공간에서 깨어난다. |
| 공간 | 꿈속 허브. 사무실과 닮았지만 어긋난 공간. |
| 플레이 상태 | 제한적 이동/관찰. |
| 시작 트리거 | 횡단보도 사고 후 암전 종료. |
| 종료 조건 | 쪽지 또는 PC를 발견할 수 있는 상태로 전환. |

### 공간 콘셉트
- 사무실과 비슷하지만 창문/문/복도 배치가 비정상적이다.
- 현실 사무실의 오브젝트가 일부 반복된다.
- 조명이 간헐적으로 깜빡인다.
- 모니터는 꺼져 있거나 노이즈만 나온다.

### StoryFlow Shot 구성

| ShotID | 내용 | 구현 메모 |

## 8. 주의점

- 미니게임 세부 구현은 아직 후순위다.
- 지금 중요한 것은 **완성도 높은 한 씬**이 아니라 **전체 흐름이 끊기지 않는 구조**다.
- StoryFlow SceneID와 SaveGame 진행 키는 초기에 고정하는 편이 좋다.
