# 챕터-씬-기획서

> 기준 문서: `기획/스토리기획.md`, `기획/개발기획.md`  
> 목적: 챕터 단위 스토리 기획을 Unreal Engine 5 / StoryFlow 구현 단위인 Scene / Shot / Save 지점으로 세분화한다.  
> 상태: 1차 제작용 초안. 인물 이름, 괴담 사이트명, 미니게임 세부 룰은 추후 확정 필요.

---

## 0. 문서 역할

`스토리기획.md`가 전체 서사와 챕터 방향을 다룬다면, 이 문서는 실제 제작자가 바로 StoryFlow 자산으로 옮길 수 있도록 아래 항목을 정리한다.

- 각 챕터를 어떤 Scene으로 나눌지
- 각 Scene 안에서 어떤 Shot이 순서대로 실행될지
- 플레이어 조작 가능/불가능 구간이 어디인지
- 어떤 조사/상호작용이 필수인지
- 어디서 저장/복구가 가능한지
- 어떤 Save Key가 갱신되어야 하는지
- 미니게임이 더미 상태여도 전체 StoryFlow가 끝까지 이어지려면 무엇이 필요한지

## 1. 공통 설계 원칙

### 1-1. 핵심 정서 곡선

```text
현실의 몰락
→ 특종 욕망
→ 사고
→ 꿈속 사이트 진입
→ 규칙 공포
→ 감시 공포
→ 추격 공포
→ 죄의 직접 형상화
→ 병실 무력감
→ 반성 없는 최후
```

플레이어는 주인공을 처음에는 생존 압박에 몰린 기자로 보지만, 챕터가 진행될수록 주인공이 피해자가 아니라 심판 대상이라는 사실을 알게 된다.

### 1-2. 주인공 표현 원칙

주인공은 끝까지 반성하지 않는다.

- 직접적인 속죄보다 자기합리화 중심
- 공포를 느껴도 죄책감보다 억울함/분노/불안이 먼저 나옴
- 낙인을 얻을 때마다 “왜 나한테 이런 일이”라는 반응이 기본
- 마지막 소원도 용서나 사죄가 아니라 다시 출세하는 것

### 1-3. Scene 분리 기준

아래 중 하나라도 바뀌면 별도 Scene으로 나눈다.

- 맵 또는 공간이 바뀐다.
- 플레이 목적이 바뀐다.
- 조작 상태가 바뀐다.
- 컷신 중심에서 탐색/플레이 중심으로 바뀐다.
- 저장 체크포인트로 삼을 만하다.
- 미니게임 진입/클리어/복귀 지점이다.
- UI 중심 진행과 3D 월드 진행이 전환된다.

### 1-4. Shot 분리 기준

Shot은 Scene 내부의 최소 진행 단위다.

- 페이드 인/아웃
- 입력 잠금/해제
- 자막/대사 출력
- 카메라 강제 전환
- 특정 오브젝트 조사 대기
- UI 표시/닫기
- 공포 이벤트 1회 발생
- Save Key 갱신
- 다음 Scene 전환

## 2. ID / 네이밍 규칙

### SceneID

```text
CH##_S##
```

예:

```text
CH01_S01
CH02_S04
CH06_S05
```

현재 예외:

```text
Scene_Intro
```

### ShotID

```text
S##_###
```

예:

```text
S01_001
S01_010
S04_030
```

### 자산명 기준

| 구분 | 규칙 | 예시 |
|---|---|---|
| StorySceneAsset | `CH##_S##_Asset` | `CH01_S01_Asset` |
| Scene Template | `CH##_S##` | `CH01_S01` |
| Shot Asset | `S##_###` | `S01_001` |
| 공통 Shot | `Shot_기능명` | `Shot_ShowWidget` |
| Branch Template | `Branch_조건명` | `Branch_ShouldLoadGame` |
| Registry | 고정 | `DA_StorySceneList` |

파일명과 ID에는 설명용 Slug를 붙이지 않는다. 설명은 StoryFlow 에셋의 DisplayName / Description / 이 문서의 목적 칸에 적는다.

## 3. 전역 진행 상태 / Save Key

| Key | 용도 | 최초 변경 후보 |
|---|---|---|
| `StoryFlowRef` | 현재 SceneID + ShotID 저장 | 모든 주요 체크포인트 |
| `CurrentChapter` | 현재 챕터 | 각 챕터 첫 Scene |
| `Brand_01_Oppression` | 첫 번째 낙인 획득 여부 | `CH02_S05` |
| `Brand_02_Bystanding` | 두 번째 낙인 획득 여부 | `CH03_S04` |
| `Brand_03_Exploitation` | 세 번째 낙인 획득 여부 | `CH04_S05` |
| `Scenario_01_Clear` | PC방 시나리오 클리어 여부 | `CH02_S04` 완료 |
| `Scenario_02_Clear` | 무궁화 시나리오 클리어 여부 | `CH03_S03` 완료 |
| `Scenario_03_Clear` | 숲 탈출 시나리오 클리어 여부 | `CH04_S04` 완료 |
| `EndingUnlocked` | 병실 엔딩 진입 가능 여부 | `CH05_S04` 완료 |

저장 후보 지점:

- Scene 시작 시점
- 컷신 완료 후 조작이 풀리는 시점
- 필수 상호작용 완료 시점
- 미니게임 시작 직전
- 미니게임 클리어 직후
- 낙인 획득 직후
- 챕터 전환 직전
- 병실 엔딩 진입 직전

## 5. Scene_Intro. 로비 인트로 / 시작 분기

### 목적

- 새 게임과 이어하기를 분기한다.
- 저장된 `StoryFlowRef`가 있으면 이어하기로 복구한다.
- 새 게임이면 본편 시작점 `CH01_S01`로 이동한다.

| ShotID / Template | 트리거 | 플레이어 상태 | 연출/기능 | 저장/분기 | 다음 |
|---|---|---|---|---|---|
| `Branch_ShouldLoadGame` | 인트로 시작 | UI 조작 | 저장 데이터 존재 여부 확인 | 저장 있음/없음 분기 | `Shot_LoadGame` 또는 `CH01_S01` |
| `Shot_LoadGame` | 이어하기 선택 | 입력 잠금 | 저장된 `StoryFlowRef` 로드 | 기존 Ref 사용 | 저장된 Scene/Shot |
| `S_Intro_NewGame` | 새 게임 선택 | 입력 잠금 | 검은 화면 전환 | `StoryFlowRef = CH01_S01/S01_001` | `CH01_S01` |

검증 기준:

- 저장 데이터가 없으면 새 게임으로 자연스럽게 시작한다.
- 저장 데이터가 있으면 저장된 Scene/Shot으로 복구된다.
- 새 게임 시작 시 `CH01_S01`로 진입한다.

# CH01. 신문사 도입

## 챕터 목적

주인공의 현실 상태, 출세 욕망, 몰락, 딸 부양 압박을 전달한다. 수신불명의 제보 전화로 사건을 시작하고, 횡단보도 사고를 통해 현실 레이어를 끊어 꿈속 사이트로 진입시킨다.

## 정서 곡선

```text
무기력한 일상 → 회사 내 압박 → 특종 가능성 → 욕망의 재점화 → 불길한 전화 → 사고 충격
```

## 공개 정보

- 주인공은 좌천된 기자다.
- 해고 위기 또는 조직 내 퇴출 압박을 받고 있다.
- 딸을 부양해야 한다.
- 주인공은 다시 올라가고 싶어 한다.
- 실종 사건/괴담 사이트 제보가 들어온다.
- 제보를 따라 움직이려는 순간 사고가 발생한다.

## Scene 목록

| SceneID | 이름 | 목적 | 플레이 형태 | 예상 시간 |
|---|---|---|---|---|
| `CH01_S01` | 좌천된 기자의 자리 | 주인공의 현재 처지 전달 | 컷신 + 짧은 입력 전환 | 2~3분 |
| `CH01_S02` | 사무실 조사 | 상황/인물 정보 제공 | 3D 조사 | 4~5분 |
| `CH01_S03` | 수신불명 전화 | 제보와 특종 욕망 제시 | 대화/전화 이벤트 | 2~3분 |
| `CH01_S04` | 퇴근길 횡단보도 사고 | 현실 종료, 꿈 진입 | 이동 + 사고 컷신 | 2~3분 |

## CH01_S01. 좌천된 기자의 자리

목적:

- 주인공이 대형 신문사의 변두리 부서로 밀려난 기자임을 보여준다.
- 플레이어가 “현재 주인공은 몰락한 상태”라는 정보를 먼저 받아들이게 한다.
- 조작 전에 공간 분위기와 주인공의 위치를 각인한다.

| ShotID | 트리거 | 플레이어 상태 | 연출/이벤트 | 대사/텍스트 방향 | 저장/분기 | 다음 |
|---|---|---|---|---|---|---|
| `S01_001` | Scene 시작 | 입력 잠금 | 검은 화면에서 사무실 소음 페이드 인 | 없음 | `StoryFlowRef` 저장 | `S01_010` |
| `S01_010` | 자동 | 입력 잠금 | 형광등 깜빡임, 낡은 책상/파티션 패닝 | “여긴 더 이상 취재부가 아니다.” | 없음 | `S01_020` |
| `S01_020` | 자동 | 입력 잠금 | 주인공 책상 클로즈업 | 좌천/해고 위기 암시 | 없음 | `S01_030` |
| `S01_030` | 자동 | 입력 잠금 | 휴대폰 알림 또는 딸 사진 노출 | 딸 부양 압박 암시 | 없음 | `S01_040` |
| `S01_040` | 자동 | 입력 해제 | 카메라 플레이어 시점 복귀 | “퇴근 전에 정리할 게 있다.” | `StoryFlowRef` 저장 | `CH01_S02` |

검증 기준:

- 주인공의 사회적 몰락이 대사 없이도 전달된다.
- 플레이어가 다음 행동 목표를 이해한다.
- 이어하기 시 입력 해제 직전/직후에서 어색하지 않게 복구된다.

## CH01_S02. 사무실 조사

목적:

- 플레이어가 직접 조사하면서 주인공의 배경을 이해한다.
- 딸, 해고 위기, 과거 특종 욕망을 오브젝트로 전달한다.
- 전화 이벤트 전까지 최소한의 현실 몰입을 만든다.

필수 조사 오브젝트 후보:

| 오브젝트 | 공개 정보 | 성격 |
|---|---|---|
| 해고/인사 관련 문서 | 회사가 주인공을 밀어내고 있음 | 필수 |
| 딸 사진 또는 문자 | 주인공에게 부양 압박이 있음 | 필수 |
| 과거 기사 스크랩 | 한때 잘나가던 기자였음 | 선택 |
| 동료 기자 관련 낡은 메모 | 후반 진실의 씨앗 | 선택 |
| 여직원 이름이 지워진 자료 | 챕터 4 복선 | 선택 |

| ShotID | 트리거 | 플레이어 상태 | 연출/이벤트 | 대사/텍스트 방향 | 저장/분기 | 다음 |
|---|---|---|---|---|---|---|
| `S02_001` | Scene 시작 | 이동 가능 | 조사 목표 표시 | “책상 주변을 확인하자.” | `StoryFlowRef` 저장 | 대기 |
| `S02_010` | 해고 문서 조사 | 상호작용 중 | 문서 UI/텍스트 표시 | 회사 압박, 계약/징계 암시 | 조사 플래그 저장 후보 | 대기 |
| `S02_020` | 딸 관련 물건 조사 | 상호작용 중 | 사진/문자 표시 | 부양 압박, 자기합리화 | 조사 플래그 저장 후보 | 대기 |
| `S02_030` | 과거 기사 조사 | 상호작용 중 | 기사 스크랩 표시 | “그때처럼 한 방이면 된다.” | 선택 조사 | 대기 |
| `S02_040` | 필수 조사 충족 | 이동 가능 | 휴대폰 미세 진동/화면 점멸 | 불길한 전조 | `StoryFlowRef` 저장 | `S02_050` |
| `S02_050` | 자동 또는 자리 이탈 | 이동 가능 | 퇴근 목표 활성화 | “이제 나가자.” | 없음 | `CH01_S03` |

검증 기준:

- 플레이어가 왜 주인공이 제보에 매달리는지 이해한다.
- 조사 완료 조건이 명확하다.
- 필수 조사 전에는 전화 이벤트가 너무 갑작스럽게 발생하지 않는다.

## CH01_S03. 수신불명 전화

목적:

- 쌍둥이 여동생의 첫 개입을 시작한다.
- 실종 사건과 괴담 사이트 제보를 던진다.
- 주인공이 속죄가 아니라 특종 욕망 때문에 움직인다는 점을 보여준다.

| ShotID | 트리거 | 플레이어 상태 | 연출/이벤트 | 대사/텍스트 방향 | 저장/분기 | 다음 |
|---|---|---|---|---|---|---|
| `S03_001` | Scene 시작 | 이동 가능 | 휴대폰 진동 반복 | 발신자: 수신불명 | `StoryFlowRef` 저장 | `S03_010` |
| `S03_010` | 전화 받기 | 입력 제한 | 주변 사운드 저하, 전화 음성 강조 | “기자님, 아직 특종 찾고 계시죠?” | 없음 | `S03_020` |
| `S03_020` | 자동 | 입력 제한 | 실종 사건/사이트 키워드 제시 | 괴담 사이트, 사라진 사람, 제보 | 없음 | `S03_030` |

|---|---|---|---|---|---|---|
| `S04_001` | Scene 시작 | UI 조작 제한 | 사이트 소원 입력창 표시 | “당신의 소원을 입력하십시오.” | `StoryFlowRef` 저장 | `S04_010` |
| `S04_010` | 자동 또는 선택 | UI 조작 | 입력 후보 표시 | “다시 올라가고 싶다 / 특종을 원한다 / 원래 자리로” | 없음 | `S04_020` |
| `S04_020` | 소원 확정 | 입력 잠금 | 입력창이 피처럼 번짐 | “접수되었습니다.” | `EndingUnlocked = true` | `S04_030` |
| `S04_030` | 자동 | 입력 잠금 | 원혼 손이 화면을 덮음, 병원 소리 급증 | 없음 | `StoryFlowRef = CH06_S01/S01_001` 후보 | `CH06_S01` |

선택지가 여러 개처럼 보여도 모두 같은 욕망으로 귀결된다.

- 다시 올라가고 싶다
- 특종을 원한다
- 내 자리를 돌려줘

용서/사죄 선택지는 제공하지 않는 편이 현재 캐릭터 방향에 맞다. 만약 제공하더라도 선택 불가/글리치 처리로 주인공의 본심이 아니라는 식으로 연출한다.

# CH06. 병실 엔딩

## 챕터 목적

꿈과 현실을 접합하고 복수 구조를 완성한다. 플레이어는 선택지를 보지만 실제로 말할 수 없고, 주인공은 코마 상태의 무력함 속에서 최후를 맞는다.

```text
의식 회복 착각 → 조작 불능 인지 → 딸/의료진 대화 청취 → 말하려 하지만 실패 → 쌍둥이 여동생 정체 공개 → 사고 가해자/아버지 복수 확인 → 원혼 등장 → 최후
```

- 말하기 선택지 UX
- 간호사 정체 공개 컷신
- 최후 연출

## 9. 구현 검증 체크리스트

### 공통

- [ ] 모든 SceneID가 `DA_StorySceneList` 또는 대응 Registry에 등록된다.
- [ ] 각 Scene 시작 Shot에서 `StoryFlowRef` 저장 후보가 명확하다.
- [ ] 미니게임 클리어 후 Save Key가 갱신된다.
- [ ] 이어하기 시 현재 Scene/Shot으로 복구된다.
- [ ] 입력 잠금/해제 구간이 꼬이지 않는다.
- [ ] UI 중심 Scene과 3D 조작 Scene 전환이 끊기지 않는다.

### 챕터별

- [ ] CH01: 주인공의 몰락/딸/특종 욕망/사고가 전달된다.
- [ ] CH02: 괴담 사이트와 첫 번째 낙인 구조가 이해된다.
- [ ] CH03: 감시/방관 테마와 동료 기자 사건이 연결된다.
- [ ] CH04: 여직원 사건과 착취의 죄가 드러난다.
- [ ] CH05: 추락 원혼 이미지와 마지막 소원 입력이 연결된다.
- [ ] CH06: 병실 반전, 쌍둥이 여동생, 아버지 복수, 최후가 이해된다.

## 10. 문서 사용 방법

개발 작업 시에는 아래 순서로 사용한다.

1. 만들 SceneID를 고른다.
2. 해당 Scene의 목적/진입 조건/종료 조건을 확인한다.
3. Shot 플로우 표를 기준으로 StoryFlow Shot을 만든다.
4. 저장 후보가 있는 Shot에는 `StoryFlowRef` 갱신을 연결한다.
5. 미니게임 또는 상호작용이 아직 없으면 더미 완료 조건으로 먼저 연결한다.
6. 챕터 끝까지 연결한 뒤 각 미니게임을 구체화한다.

이 문서는 1차로 “전체 흐름이 끝까지 이어지는 것”을 우선한다. 개별 미니게임의 세부 룰, 대사 전문, 컷신 콘티는 이후 별도 문서 또는 본 문서의 하위 섹션으로 확장한다.
